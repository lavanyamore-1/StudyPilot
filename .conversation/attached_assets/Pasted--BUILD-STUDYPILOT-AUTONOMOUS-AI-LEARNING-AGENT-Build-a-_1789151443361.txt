# BUILD: STUDYPILOT — AUTONOMOUS AI LEARNING AGENT

Build a complete, polished, working web application called **StudyPilot** for an Agentic AI Hackathon.

## 1. CORE CONCEPT

StudyPilot is NOT a normal AI chatbot and NOT simply an AI timetable generator.

It is an **autonomous, goal-driven AI learning agent** that:

**OBSERVE → PLAN → DECIDE → ACT → EVALUATE → ADAPT → ACT AGAIN**

The user provides an academic goal such as:

> "I have a DBMS exam in 7 days and want to score 80%+."

StudyPilot should independently analyze the goal, syllabus, available study time, previous performance and study resources, create a plan, execute learning tasks, evaluate the student's performance through quizzes, detect weaknesses, and dynamically modify the plan.

The application must clearly demonstrate that **agentic behavior is necessary**.

---

# 2. PRIMARY HACKATHON DEMONSTRATION

The application must support this complete workflow:

### GOAL

Student enters:

* Subject: DBMS
* Exam date: 7 days from today
* Target score: 80%
* Available study time: 3 hours/day
* Current confidence: Medium
* Weak topics: SQL, Transactions

### OBSERVE

Agent analyzes:

* syllabus
* topic importance
* previous performance
* available time
* target score
* weak topics
* previous quiz results

### PLAN

Agent creates a dynamic study strategy.

Example:

Day 1:

* SQL basics
* SQL queries

Day 2:

* Normalization
* ER modeling

Day 3:

* Transactions
* Concurrency

etc.

### ACT

The agent should execute tasks such as:

* generate study material
* generate summaries
* generate questions
* generate quizzes
* analyze answers
* recommend the next topic
* update progress

### EVALUATE

After a quiz, calculate:

* score
* topic-wise performance
* confidence
* weak concepts
* readiness score

### ADAPT

If the student performs badly in Transactions, the agent must NOT simply continue with the original plan.

It should automatically say something like:

> "Your performance in Transactions is below the target threshold. I am adapting your study plan by increasing practice time for Transactions and reducing time allocated to topics where you are already strong."

Then modify the future schedule.

### FINAL OUTCOME

Show improvement such as:

Initial readiness: 58%

After adaptive learning:

Final readiness: 86%

This should be visible in the dashboard.

# 3. IMPORTANT: MAKE IT A REAL AGENT

The system must visibly demonstrate:

## Goal-driven execution

The agent has a measurable objective:

> Reach target academic readiness / target score before exam date.

## Dynamic action selection

The agent chooses what action to perform next based on the current state.

Possible actions:

* ANALYZE_SYLLABUS
* CREATE_PLAN
* GENERATE_NOTES
* GENERATE_QUIZ
* ANALYZE_QUIZ
* IDENTIFY_WEAKNESS
* REPLAN
* RECOMMEND_TOPIC
* GENERATE_PRACTICE
* UPDATE_PROGRESS

## Multi-step execution

The agent should perform several actions sequentially rather than answering once.

## Adaptation

The plan must change when the student's performance changes.

## Robustness

Handle situations such as:

* poor quiz performance
* missed study session
* incomplete syllabus
* insufficient study time
* API failure
* unavailable resource
* unexpected low score

Provide graceful fallback behavior.

# 20. AGENT CONTROLLER

Implement an actual agent controller rather than only hardcoded UI transitions.

Create a central agent state such as:

```text
student_goal
exam_date
target_score
current_readiness
topic_mastery
available_time
study_plan
quiz_history
current_state
last_action
next_action
```

The controller should determine the next action based on the current state.

Example logic:

```text
IF goal is missing:
    request goal

ELSE IF syllabus is missing:
    analyze available syllabus

ELSE IF no study plan:
    create plan

ELSE IF quiz result exists:
    evaluate result

IF weak topic detected:
    generate targeted practice

IF missed session:
    replan

IF readiness >= target:
    switch to revision mode

ELSE:
    continue adaptive learning
```

Use an LLM where appropriate for reasoning and decision-making.
